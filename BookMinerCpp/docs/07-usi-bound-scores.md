# USI の境界値付き評価値

`info` の `score` に `lowerbound` または `upperbound` が付く場合、その値は探索が報告した下界または上界であり、確定値とは限らない。BookMinerCpp はこれらも候補手の評価値として採用する。探索終了時に境界値付きの PV しか出力されない場合があるためである。境界値を一律に捨てるべきだという実験的根拠は得られなかった。

## 2026-10-29 の実験

YaneuraOu の `SFNN_halfka2_2304_15_64_progress8` baseline エンジンと、`inbox/evalTuyo12-20261025` の `nn.bin`、`progress.bin`、`eval_options.txt`（`FV_SCALE 24`）を使用した。ログで両バイナリの読み込みを確認した。Threads 1、USI_Hash 64 MB、定跡無効、各局面で新規ゲーム、`go nodes 100000` とし、初期局面と `7g7f`、`2g2f`、`7g7f 3c3d` を指した計4局面を調べた。

通常の `PvInterval 300` で MultiPV 1 のとき、4局面中3局面で、最後の第1候補のスコアは境界値付きだった。この3局面では、探索中に確定値付きの第1候補 PV は出力されなかった。MultiPV 4 の4局面では、最後の第1候補はすべて確定値付きだったが、他の候補に境界値付きのものがあった。`PvInterval 0` でも MultiPV 1 の4局面中3局面で最後の第1候補は境界値付きだった。

追加で、同じ局面について別途 `go depth` で探索を完了させた。次の表は 100,000 ノードでの最終出力と、深さ固定探索での最後の確定値である。3例とも PV の初手は一致した。

| 局面 | ノード制限での最終スコア | 深さ固定での確定スコア | 差の絶対値 |
| --- | ---: | ---: | ---: |
| 初期局面 | 52 upperbound | 64（depth 14） | 12 |
| `7g7f` 後 | -93 lowerbound | -101（depth 16） | 8 |
| `2g2f` 後 | -44 lowerbound | -42（depth 16） | 2 |

これは別々に実行した、終了条件の異なる探索の比較である。ノード制限によって途中で停止した探索と、深さ固定で完了した探索では状態が異なるため、差を境界値の厳密な誤差とみなすことはできない。局面数も少なく、評価値の差の一般的な分布や、他のエンジン・探索条件での挙動は判断できない。
